Watchdog Internet Reboot Box

ESP32-based network watchdog that quietly power-cycles your fibre ONT and router when connectivity dies, then stands back.

ESP32 DevKit v1 ESP RainMaker Network watchdog Automatic power-cycling

Overview

This little box sits quietly on the network and keeps an eye on the internet for you. Every 30 seconds it checks connectivity by pinging Google’s DNS (8.8.8.8) and trying to load a tiny “204 No Content” page from Google. If both checks pass, it does nothing. If they fail twice in a row, it takes control of the power to your fibre ONT and router, reboots them in a safe sequence, then waits for everything to stabilise before it stands down again.

I built it because my wife works online, and our internet connection would periodically die in a way that only a full power-cycle of the landlord’s router and ONT would fix. The main gear lived in his house, and constantly asking him to reboot it was not practical. This box makes those problems disappear in the background and exposes a simple app interface for when you want more direct control.

How it works

The core logic runs on an ESP32 DevKit v1 and is exposed through an ESP RainMaker app. When monitoring is enabled from the app, the state machine looks roughly like this:

  • Every 30 seconds:
    • Ping 8.8.8.8.
    • Attempt to fetch a tiny Google “204 No Content” page.
  • If both tests pass:
    • Show “Internet OK” in the app.
    • Keep both the fibre box and router powered.
    • Clear internal failure counters.
  • If the tests fail twice in a row (~1 minute with no internet):
    • Turn OFF both the fibre box and router via MOSFET relays.
    • Keep them off for the configured off-time (default 30 seconds).
    • Turn the fibre box ON, then wait 10 seconds.
    • Turn the router ON.
    • Show “Stabilising…” and wait the stabilisation timeout (default 2 minutes).
  • Each full reboot sequence counts as an attempt. Once the number of attempts reaches max_attempts (default 3), the system stops trying and enters a lockout period (default 6 hours) so it does not endlessly reboot your gear.

All of these timings and limits can be tuned from the Settings tile in the app without reflashing firmware.

Controls & status

Through the ESP RainMaker app you can:

  • Toggle monitoring on/off remotely.
  • Manually trigger a power-cycle with a dedicated button — useful if the internet feels “off” but hasn’t fully failed the tests yet.
  • Reset attempt counters and lockout with another button so the box is allowed to start trying again immediately.
  • Adjust key timings:
    • Off-time (how long both ONT and router stay off).
    • Stabilisation time (how long the system waits after power-up before it judges connectivity again).
    • Max attempts before lockout.
    • Lockout duration in hours.

A simple status LED on the enclosure mirrors what the app is saying:

  • Solid ON: Internet OK, monitoring active.
  • Blinking: Internet tests are failing / reboot logic is in progress.

Hardware & wiring

The project is intentionally simple on the hardware side — a robust ESP32, two low-voltage control channels, and one status LED:

  • Microcontroller: ESP32 DevKit v1.
  • Power switching: 2 × MOSFET relay modules (one for the fibre ONT, one for the router).
  • Indicator: Single LED with series resistor for status feedback.
  • Enclosure & mounts: 3D printed case, mounting brackets, and strain relief for cabling.
  • Power: The ESP32 is powered from a stable low-voltage source; the relays switch mains or low-voltage to the ONT/router depending on your setup.

All of the wiring, enclosure design, 3D printing, and troubleshooting were done from scratch. I also leaned on AI-assisted coding for parts of the firmware, then refined the logic by hand once the core state machine and RainMaker plumbing were in place.

Development notes

This was my first proper ESP-IDF / RainMaker project built fully in VS Code. I initially tried to get RainMaker working via the Arduino IDE, but ran into limitations and configuration issues. Moving to VS Code forced me to learn the ESP-IDF toolchain properly: configuring the project, handling partitions, managing credentials and provisioning, and wiring up the RainMaker devices, parameters and actions.

Once the basics were stable, I focused on making the behaviour predictable and safe:

  • Guarding all power actions behind clear state transitions and counters.
  • Ensuring that ONT power-up always happens before router power-up.
  • Making all timings configurable from the app instead of hard-coded.
  • Adding a lockout window so the box cannot get stuck in a reboot loop.

The result is a small, dedicated tool that just does its job quietly in the background — no more late-night messages to the landlord asking for a manual reset.
